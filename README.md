# 育兒同行 Alongside

新北市與臺北市幼兒園與托嬰中心的資訊整理站。純靜態，部署在 Firebase Hosting 免費方案，現金支出 0 元。

規劃背景與決策理由見 [托育網站規劃文件.md](托育網站規劃文件.md)，設計規格見 [ui-mockup.html](ui-mockup.html)。

## 它做什麼

把散在好幾個網站的資訊集中成一頁：機構基本資料、幼兒園月費、裁罰紀錄，
地圖與家長評價連到 Google 地圖，評鑑與補助導向主管機關的官方查詢頁。

本站不評分、不排名、不轉載評論。

## 資料來源與其限制

**一、各縣市政府的開放資料**（每月自動抓取）

| 縣市 | 幼兒園 | 托嬰中心 | 幼兒園骨幹 |
| --- | --- | --- | --- |
| 新北市 | 1,111 | 382 | 市府開放資料 |
| 臺北市 | 743 | 252 | **民間封存** |

**兩市的資料韌性不同，這點不能含糊。** 新北市有市府層級的幼兒園名冊，
封存只是加值層——上游消失時新北的幼兒園還在，只失去收費與裁罰。
臺北市沒有對應的市府開放資料，幼兒園名冊本身就取自封存，上游消失就整批不見。
`institutions.json` 的 `cities[].preschoolBackbone` 記錄這個差異，授權頁與頁尾都會照實說明。

托嬰中心則是各縣市自己發布，平台、格式、欄位全都不同，每加一個縣市就要寫一段剖析
（`fromNtpcNursery` / `fromTaipeiNursery`）。臺北市的 CSV 沒有行政區欄位，要從地址剖析；
私立那份也沒有收托人數。**這就是為什麼擴張的成本主要在托嬰，不在幼兒園。**

**二、台灣幼兒園地圖封存資料**（[kiang/ap.ece.moe.edu.tw](https://github.com/kiang/ap.ece.moe.edu.tw)，MIT 授權）

g0v 江明宗長期以自動化腳本備份全國教保資訊網，涵蓋全國 22 縣市，提供政府開放資料沒有的欄位：
分齡收費、裁罰明細、立案字號、核定人數、面積、座標、園所官網。
雙北 1,854 間幼兒園中 1,680 間有分齡收費、744 間有裁罰共 2,165 筆。

封存資料含已停辦機構與同名重複，兩者都會造成主鍵碰撞，處理方式見 `fetchInstitutions()`：
已停辦（`is_active=0`）不收錄；同名時一律以營運中的那筆為準——實測臺北市有搬遷案例
（舊址停辦、新址營運，兩筆同名），若讓後寫入的覆蓋，會把停辦分部的座標與收費掛到營運中的機構上。

這個來源有四個必須誠實面對的限制，程式與頁面上都做了對應處理：

| 限制 | 處理方式 |
| --- | --- |
| 不是政府開放資料，是民間對官網的備份 | 每個使用它的區塊都標示出處、作者、授權與備份日期 |
| 官方公告有時效會下架，備份可能留有官方已查不到的舊紀錄 | 機構頁的裁罰區塊置頂四點說明，並附官方即時查詢連結 |
| 只涵蓋幼兒園，382 間托嬰中心無對應資料 | 托嬰中心頁面不顯示這些欄位；概況頁明講統計不含托嬰 |
| 上游若停止維護，資料會無聲變舊 | `ARCHIVE_MAX_AGE_DAYS`（120 天）過期就整批不採用，頁面自動退回只有開放資料的版本 |

### 收費欄位的語意是驗證出來的，不是猜的

封存 GeoJSON 有一個 `monthly` 欄位，但它對 1,057 間中的 782 間（74%）對不上任何年齡的
實際收費，也不是各齡平均，來源無法解釋，已棄用。

改用 `summary1/新北市/{2,3,4,5}.csv` 的分齡資料。欄位語意用同一來源的收費明細表
（`slip114`，園所依法申報的原始文件）反推並交叉驗證：

| 等式 | 樣本驗證 |
| --- | --- |
| `monthly1 = total1 ÷ months` | 40/40 |
| 全學期總收費 = 學費＋雜費＋材料費＋活動費＋午餐費＋點心費 | 20/20 |
| `total1 = 上學期總收費 × 2` | 19/20 |
| `total2 = 課後延托費 × 2` | 17/20 |

結論：**`monthly1` 是每月必繳費用，未扣任何政府補助，不含交通費與課後延托費。**
`monthly2` 是課後延托費的月攤，屬選繳——一開始誤以為是補助，驗證後推翻。

因此頁面一律分齡呈現並標明年齡（2 歲與 5 歲可差三千以上），且明講「未扣補助」。
`收費月數` 同時用來回答家長最常問的「有沒有寒暑假」：12 個月為全年收費，
9 個月為學期制、寒暑假需另外安排——這是代理指標而非直接答案，頁面上有說明。

非營利與職場互助的收費全國都是同一個數字，那是政策訂的收費上限而非實際分布，
`feeByOwnership()` 會用 `flat` 標記。家數少於 10 間的類型不畫進圖表，只留在表格。

### 補助試算

本站顯示的是園所收費，不是家長實付。一間準公共園申報 12,274，家長第 1 胎其實只付
3,000，差額由政府直接撥給園所——沒有這層換算，家長並排看到「準公共 12,274」與
「私立 11,641」會以為差不多，實際差了四倍。這是主動誤導，不只是資訊不足。

`src/lib/subsidy.js` 集中所有政策數字（111 年 8 月起適用，取自教育部全國教保資訊網）：

| 類型 | 第 1 胎 | 第 2 胎 | 第 3 胎以上 | 低收／中低收 |
| --- | --- | --- | --- | --- |
| 公立 | ≤1,000 | 免費 | 免費 | 免費 |
| 非營利、職場互助 | ≤2,000 | ≤1,000 | 免費 | 免費 |
| 準公共 | ≤3,000 | ≤2,000 | ≤1,000 | 免費 |
| 私立等（育兒津貼） | 5,000 | 6,000 | 7,000 | — |

兩種補助的機制完全不同，UI 分開講：平價教保是**入學自動減免**，家長只繳上限內金額；
育兒津貼是**匯進家長帳戶**，要自己申請，學費照付。

準公共的上限明確涵蓋「學費、雜費、材料費、活動費、午餐費及點心費」，
正好就是本站 `monthly` 的六個項目，兩者可直接相減。

`verify.js` 把這四組數字釘住，改動時必須有意識地一起改。

### 加一個縣市要改哪裡

`scripts/fetch-data.js` 的 `CITIES` 陣列是唯一的設定入口，加一筆就多一個縣市。
但實際還要處理三件事，這就是每個縣市 2–3 天的來源：

1. **托嬰中心的剖析器**——各縣市欄位不同，要寫一個 `fromXxxNursery`。
2. **八個官方連結**——`src/lib/site.js` 的 `CITY_LINKS`。托嬰的四個各縣市完全不同；
   幼兒園只有「收退費」是地方的，裁罰與評鑑走全國教保資訊網、育兒津貼走教育部。
   連結一律用 `kind` 查找而非標籤文字：新北叫「裁罰公告」、臺北叫「違反兒少法公告」，
   用文字比對會在加新縣市時默默失效。
3. **行政區重名**——目前雙北 41 區無重名，網址可直接用區名。加入第三個縣市前
   要先確認（例如三民區、中正區在多個縣市都有），`verify.js` 有一條檢查會擋下。

**機構 ID 不含縣市**（`kind-名稱-行政區`）。新北市那 1,493 個網址已提交 Search Console，
擴充時不能改動，`verify.js` 有一條檢查釘住這件事。

### 拿不到的資料

- **上下課的實際時間**：收費明細表只區分半日班與全日班，沒有時刻。
- **托嬰中心的座標**：政府開放資料只給文字地址，地址定位服務需申請金鑰，決定不申請。
  因此距離排序只涵蓋幼兒園，頁面上明講。
- **名額、抽籤時程、師生比、教育理念**：無任何開放資料。

### 資料處理階段就過濾掉的東西

這些不是顯示層的隱藏，是在 `fetch-data.js` 就不寫進 `institutions.json`，
所以版控裡也不會有：

- **個人姓名。** 原始裁罰公告含「負責人：某某」「行為人：某某」，全市共 477 位可識別自然人。
  `toRole()` 只保留角色。家長選的是機構不是個人，而公開自然人的裁罰紀錄——尤其官方已下架之後——
  涉及個資與名譽，風險高於它帶來的價值。
- **不可信的園所連結。** `safeWebsite()` 擋掉學校內網 IP、缺 TLD 的殘缺網址、帶帳號資訊的網址
  （來源實際出現過打錯成 email 的 `http:/someone@yahoo.com.tw`，會被解析成 userinfo）、
  短網址與已停止服務的部落格平台，並輸出正規化後的 `url.href` 而非原始字串。
  553 筆過濾後剩 329 筆。

### 授權與聲明

`/授權/` 頁載明兩個來源的授權條款（政府資料開放授權條款第 1 版、MIT 完整聲明）、
本站對原始資料所做的加工、Google 商標聲明、字型未散布聲明，以及更正下架管道。
`DataNotice` 元件把「資料為程式自動整理、可能有誤、請以原始資料為準」的聲明
連同可點的原始資料集連結放在每一種頁型上，頁尾另有一份。

## 指令

```bash
npm install           # 安裝相依套件
npm run fetch         # 只抓資料，更新 institutions.json 與搜尋索引
npm run dev           # 本機開發伺服器 http://localhost:4321
npm run build         # 抓資料 + 建置 + 驗證
npm run build:offline # 用現有資料建置 + 驗證，不連網
npm run verify        # 只驗證 dist/
npm run cost          # 推估免費額度還能撐多少人
npm run preview       # 預覽 dist/ 的建置結果
```

`npm run verify` 的每一條檢查都對應一個真的發生過的問題（地址被誤切、罰鍰金額解析錯誤、
`[hidden]` 被樣式蓋掉導致篩選失效、個資外洩、主管機關連結給錯……），
不是理論風險。建置與 CI 都會跑，失敗就中止部署。

## 架構

```
scripts/fetch-data.js   下載開放資料 + 封存資料 → 正規化 → src/data/institutions.json
src/lib/site.js         全站設定：網址、標籤配色、官方連結對照表
src/lib/stats.js        建置期計算所有統計，瀏覽器端不做任何運算
src/lib/subsidy.js      補助政策數字與試算，集中一處方便隨政策更新
src/scripts/shortlist.js 收藏（localStorage，無後端無帳號）
scripts/verify.js       對建置產物做 42 項回歸檢查
src/pages/index.astro   首頁（年齡分流 + 29 個行政區入口 + 全市概覽圖表）
src/pages/附近.astro     用瀏覽器定位算直線距離，跨行政區
src/pages/搜尋.astro     機構名稱搜尋（前端比對 public/search-index.json）
src/pages/收藏.astro     並排比較收藏的機構
src/pages/裁罰.astro     裁罰紀錄一覽，可依違規類型與行政區篩選
src/pages/概況.astro     新北市托育概況，完整圖表與資料來源說明
src/pages/授權.astro     資料來源與授權聲明
src/pages/d/[district]  行政區列表頁，共 41 頁；可疊加篩選、依費用排序
src/pages/i/[id]        機構頁，共 2,488 頁 ← SEO 主戰場
dist/                   建置產物，直接部署到 Firebase Hosting
```

建置產出 2,537 頁、約 59 MB。`npm run fetch` 約 20 秒（含 422 個裁罰明細檔與 4 份分齡收費）。

### 列表卡片的主要動作是「進內頁」

早期版本把「在 Google 地圖看評價」做成卡片上唯一像按鈕的元素，實測結果是使用者
全部點它、被帶離網站，從沒發現有整理過的內頁。現在整張卡是進內頁的連結
（標題連結以 `::after` 覆蓋整張卡），Google 地圖降為右下角的次要小連結。

### 篩選可疊加，不是單選

家長真正的需求是「收 2 歲 **而且** 公立」。早期版本一次只能選一個條件，
按了第二個就把第一個取消掉，等於不能用。現在每一類（機構別／屬性／年齡／裁罰）
彼此以 AND 相接，同一類內可複選、以 OR 相接。

### 收藏與比較

找托育是跨好幾週的事，家長會分很多次來看。收藏存在 `localStorage`：
不需要後端、不需要帳號、資料留在使用者裝置上，不影響純靜態與零成本，
也不用處理任何個資。代價是換裝置就沒了，這個取捨對本站划算。

`/收藏/` 用「機構當欄、欄位當列」的橫向表格——比較的重點是同一列互相對照，
縱向堆疊會讓人看不出差異。

### 首頁依年齡分流

站上的價值幾乎全在幼兒園（平均 5.6 類加值資料），而托嬰中心平均 0.0 類。
0–2 歲家長只能上托嬰中心或找保母，正好是資料最薄的一段。

與其讓他們瀏覽半天才發現什麼都沒有，首頁直接問「孩子多大了」並老實說
「這一段我們幫得有限」，同時給出社會局查詢與居家托育服務中心的入口。

### 機構頁最上面是概覽

頁面往下有收費表、補助試算、裁罰明細、官方連結四大段，每段都完整但也都要讀。
家長比較三五間時不會每間讀完，所以最上面放一組關鍵數字，五秒內回答
「這間值不值得再看下去」：補助後大約付多少、收不收我的孩子、有沒有裁罰、寒暑假、規模。

概覽的金額固定用第 1 胎、非低收、有資料的最小年齡，其他組合在下方試算區切換。
`verify.js` 有一條檢查確保概覽顯示的金額與試算結果一致，避免兩處各算各的。

### 成本監控

Firebase Spark 免費方案**無法設定用量警示**（那是 Blaze 限定），而超過每月 10 GB
的後果是**網站被停用到下個月**，不是收費——對一個家長臨時搜尋才會用到的網站，
斷線比帳單糟。

`npm run cost` 用實際的建置產物推估天花板，每次 build 會自動跑一次。
頁面變重、索引變大、收錄範圍擴張時，天花板會跟著往下掉，在 log 裡就看得到。

目前（雙北）的實測結果：

| 訪客行為 | 每人傳輸 | 每日可服務 |
| --- | --- | --- |
| 看一頁就離開 | 39 KB | 8,885 |
| 首頁→行政區→3 間機構 | 245 KB | 1,428 |
| 同上再用一次搜尋 | 765 KB | **457** |

**搜尋索引（520 KB）佔了最後那條路徑的 68%**，是目前最大的單一開銷。
再擴充收錄範圍前應先改成分縣市載入，腳本會在超過一半時發出警告。

### 沒有資料時也要說「沒有」

機構頁的收費與裁罰兩個區塊**一律出現**，即使沒有資料。
「查過、沒有」和「這站根本沒查」對家長是完全不同的資訊——
早期版本只在有資料時渲染，結果托嬰中心的頁面上什麼都看不到，無從判斷。

## 兩個容易踩到的地方

**三個資料集的地址格式不一樣。** 幼兒園是 `[220]新北市板橋區流芳里9鄰東門街30號`（含郵遞區號、縣市、
行政區、里鄰），托嬰與公托只有街段 `莊敬路46號2樓`。`toStreet()` 統一剝成街段再自己組回去。
剝除一律只在字串開頭做——實測有街名叫「區運路」，任何「切到第一個『區』字」的寫法都會把它砍壞。
另有少數資料用了異體字「新北巿」（U+5DFF）、地址中夾換行，都已處理。

**幼兒園和托嬰中心歸不同主管機關。** 幼兒園是教育部／新北市教育局，托嬰中心與公托是衛福部／新北市社會局，
兩套查詢系統完全獨立，官方連結必須依 `authority` 分開給。教育部那三個查詢頁是 ASP.NET POST 表單，
沒辦法用網址帶入園名，所以機構頁要先提供「複製機構名稱」按鈕。

## 成本紅線

只用 Firebase Hosting，不啟用 Cloud Functions / Firestore / Storage——那些會被推去綁信用卡的 Blaze 方案。
資料抓取與建置都在 GitHub Actions（免費額度內）完成，上線後的網站不依賴任何後端服務。

地圖與評價走 Google 地圖「連結」，家長點擊才由他們的瀏覽器開啟 Google，本站不呼叫任何 API，無金鑰、無用量、無費用。
